## Post

Your API reference should not live in a wiki that only your team can open.

In DocStar, an API collection is the unit you publish. Document your endpoints in a collection, publish it, and it gets its own public docs site that your users can browse.

The site is server-rendered, so the pages are fast and indexable. You can put it on a custom domain and theme it, with light and dark mode and your own navigation.

Because the docs are written in the same place as the rest of your team's documentation, the API reference does not become a separate project that drifts. The same collection also backs an MCP URL and CLI commands, but the starting point is simple: a docs site people can actually find and read.

If your API docs are still a PDF or a private page, see how a published collection looks: https://docstar.io
